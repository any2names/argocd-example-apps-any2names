# any2names fork changes

This fork of [argoproj/argocd-example-apps](https://github.com/argoproj/argocd-example-apps)
is configured to run against a local minikube setup.

## Environment

| Component       | Address                                            |
| --------------- | -------------------------------------------------- |
| Argo CD UI      | http://10.10.10.222:8002                           |
| Guestbook UI    | http://10.10.10.250:7001, http://10.10.10.72:7001  |
| Git source repo | https://github.com/any2names/argocd-example-apps-any2names |

## Changes from upstream

### Guestbook exposed on port 7001

[guestbook/guestbook-ui-svc.yaml](guestbook/guestbook-ui-svc.yaml) changes the Service from
`ClusterIP` on port 80 to `LoadBalancer` on port 7001, with `externalIPs` set to the minikube
node IPs (`10.10.10.250`, `10.10.10.72`). Traffic to `<ip>:7001` is forwarded to the pod's port 80.

A NodePort can't be used here because NodePorts are restricted to `30000-32767` by default.

### Apps point at this fork

[apps/values.yaml](apps/values.yaml) sets `config.spec.source.repoURL` to this fork, so every
`example.*` Application generated by the `apps` chart deploys from this repo's `master` branch.

The parent `apps` Application in Argo CD must also use this fork as its source, otherwise it keeps
rendering children from upstream's `values.yaml`.

### ApplicationSets point at this fork

Every `repoURL` in [applicationset/](applicationset/) (both generator inputs and templates) points
at this fork. The Pull Request generator in
[applicationset/pull-request.yaml](applicationset/pull-request.yaml) watches
`any2names/argocd-example-apps-any2names` instead of upstream.

### README links point at this fork

The `argocd app create --repo ...` examples in [blue-green/README.md](blue-green/README.md) and
the `plugins/*/README.md` files use this fork's URL.

The root [README.md](README.md) app table links each app to the local Argo CD UI at
`http://10.10.10.222:8002`. The upstream status badges were removed because GitHub can't load
images from a private IP.

## Syncing with upstream

The `repoURL` changes conflict with upstream on every update that touches those lines. To pull in
upstream changes, rebase this fork's commits onto upstream:

```sh
git fetch upstream
git rebase upstream/master
git push --force-with-lease origin master
```
